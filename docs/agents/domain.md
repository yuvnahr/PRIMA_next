# Domain docs

This repo uses a single-context layout with a root `GLOSSARY.md` and ADRs under `docs/adr/`.

Before exploring the codebase, read `GLOSSARY.md` and any ADRs relevant to the area you're working in. If either location is absent, proceed silently. The domain-modeling skill creates these docs as terminology and decisions are agreed.

Use glossary terms in issues, proposals, hypotheses, and tests. If a term is missing, check how the project describes the concept and raise any gap during domain modeling.

If a proposal conflicts with an ADR, cite the ADR and explain why the decision should be reopened.
